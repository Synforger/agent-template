# session の締め

**子のタブ (環境変数 `AGENT_CHILD=1`) は、この手順の代わりに skill `sub-agent § 子の側の決まり` で締める**。この手順は親のタブの物で、子は journal を書かずにタブのメモへ引き継ぎを書く。

Step 0〜3 を全部、この順で踏む。発動の判断 (断定形の終了発話か) は `CLAUDE.md § 終了時` が真値。

## Step 0 (発動前検証、最初に 1 回)

直近の操作者の発話に終了発話も引き金 (`Automatic session rollover` で始まる行) も無ければ幻なので終了せず作業継続。容量残と journal の採番も同時に取り、以降の Step で同じ探索を繰り返さない。検証の script を持つ派生は、それを journal の階層を引数にして流す。

**持つ票の検査** (client のタブ = `PWA_SID` が在る時): `tabs ticket mine --unsettled` を流す。動いている (待ちでない) のにこの会話で 1 行も書き足していない票が並ぶと 1 で終わる。並んだ票ごとに、次の 3 つのどれかを済ませてから Step 1 へ進む。自動の入れ替えの `tabs rollover` も同じ条件で止まる。3 で終わった時は確かめられなかった (backend が答えない等) ので、締めは止めずに進め、journal と操作者への報告に「持つ票を確かめられなかった」と 1 行書く。0 は並ぶ票が無い
- 今の状態を書き足す: `tabs ticket add <id> <file>`。file の 1 行目に次の 1 手を書く
- 待つ物があれば、理由と待つ物を本文にして待ちにする: `tabs ticket add <id> <file> --waiting`
- 終わった物は閉じる。頼まれた物は、結果を書き足して頼んだタブへ `tabs ticket pass` で返す

## Step 1 (直列、操作者承認不要)

**その session で初めて見えた** 一面 / 好み / 癖だけ、操作者の像を書く常時 load の file (`CLAUDE.md` の開始時の手順が並べる物) に **エージェント判断で追記**。**有った時だけ書く**。毎 session の更新義務はなく、既出の言い換えは対象外。書く時は Step 0 の headroom に収まる形で**1 回で書く**。

## Step 2 (並列一括、エージェント自走で完遂)

- **自動抽出 script 実行**: journal .md 書く**前に**実行。jsonl は当 session の触跡記録で、PC ローカルの artifact
  - `bash .tooling/session-end/extract-artifact-index.sh <journal-dir> --nn <NN>`: 引数は当 session が touch した階層の journal dir で、親とサブの両方なら引数を変えて 2 回流す。NN は Step 0 が出した採番をそのまま渡す。そうすると、同じ日の別の機械の journal を取り込んだ後でも番号がずれない
  - `python3 .tooling/startup/detect-duplicates.py` (重複 section cache 更新)
- **型へ返していない物の洗い出し** (必須): この session で作った形・道具の足りない所の回避・手順のうち、他でも使う物を 1 つずつ挙げ、型 (道具・テンプレ・親の skill) へ返したか、持ち主のタブへ依頼を出し切ったかを見る。どちらでもない物は締める前に出し切る。別のタブとの連絡の決めは、そのエージェントの `rules/always.md` が持つ
- **plan の棚卸し** (必須、触れた階層全部): `plans/` の生きている file を 1 本ずつ見て、**plan として終わった物だけ `_archive/` へ移す**。操作者待ちが plan の最後なら移し、途中なら残す。判断軸と手順は `rules/always.md § git` が持つ。残す file は最新化する。完了マークの付与、新規の残タスクの追加、state snapshot (develop/main の tip・open PR・branch) の更新、古い時点の記述の掃除をする。横断は `plans/` 直下、プロジェクト固有は `projects/<P>/plans/` に置く
- **説明のページの木の確かめ** (必須、触れた階層全部): skill `explainer-pages` の「続けて保つ」の確かめを全部行い、抜けをこの session で直す。何を片付けて何を残すかも同じ節が持つ
- **操作者の言葉を見本へ積む** (必須、触れた階層全部): 操作者が作った物 (ページ・スライド・図・表・文) について言った言葉を、その形を持つ道具の skill の「見本」の節へ書き足す。journal を書く前に行う
  1. `python3 .tooling/session-end/extract-operator-words.py <journal-dir> --nn <NN>` を階層ごとに 1 回流す (NN は Step 0 の採番)。書かれた `journal/<日付>/session-NN-operator-words.jsonl` の行を全部読む。行の `artifacts` は、その言葉の直前に出た作った物の path。`"source": "review"` の行は、操作者が PowerPoint で自分の手で直した頁で (文言の前後と、直す前と後の版の path つき)、一番強い「直し」として扱う
  2. 作った物の形に関わる言葉だけを選ぶ。段取り・質問・作った物の話でない発話は積まない
  3. 選んだ言葉を、強い順に「広げろ (全部・すべて・いつもと言った)」「褒め」「直し (直す前と後の組)」に分ける
  4. 書き足す先は、その形を持つ道具の skill の「見本」の節。ページ・図・表は skill `explainer-pages` の `samples.md` (このエージェントだけが持つ file で、型は配らない) で、操作者の言葉と日付を書く。**公開の道具の skill (資料の道具 pptx-agent-maker のように、repo が公開の物) には、操作者の言葉・日付・場面を書かない**。その道具の形に関わる言葉は、決まりの文 (頁の種類と決まり) だけを持ち主のタブへ `tabs send` で送る。本文の出所は「この階層の journal の <日付> の session-NN」とだけ書く (言葉は拾った `operator-words.jsonl` に残る)。持ち主は `tabs list` で選ぶ
  5. このエージェントの中の skill の 1 件には、操作者の言葉を整えずに引用し、日付と物の path を添える。**直しは言われた場面ごと書く** (どの種類の図や表の、どんな頁への言葉か)。全部の物へ広げてよいのは、「広げろ」に当たる言葉の物と、同じ直しが 2 回目に出た物だけ。1 枚への直しは、その 1 枚の直しとして書く
  6. 同じ内容の行が既に在れば、言葉と path を足すだけにする。食い違う行は新しい方を残し、古い方は「置き換えた」の 1 行を添えて節の末尾へ移す。道具の skill の決まりが操作者の言葉と食い違う時は、操作者の言葉の方へ書き直す (書けなければ持ち主へ送る)
  7. **操作者の言葉に辿れない見た目の決まりは、操作者の判断待ちにしない**。「出所なし」の印を付けて「既定」の扱いに下げ、決まりの文に「操作者の言葉と食い違ったら操作者の言葉が勝つ」と書く。操作者には訊かず、次に操作者が直しを言った時にその場で書き換える
- **vision 更新** (現在地が動いた session のみ): 触れた階層の `vision.md` を**上書き**し、動いた時だけ書き換える。毎 session の更新義務はない。中身は状態だけで、やることは `plans/` と journal が持つ。無ければ作る。**既にある行を書き換える**。段落は増やさない。節と段落数は `.tooling/docs-check/docs-check.sh` step 14 が見る
- **発火記録**: 効いた/違反 ID を `journal/<date>/session-NN-rule-hits.jsonl` へ書く。手順は `.claude/skills/rule-registry/SKILL.md` が持つ
- **ジャーナル記入**: **書く前に階層を起動 keyword から再導出**。compaction で階層文脈が消えるためで、サブプロ起動なら一番下の段の journal が正、採番アンカーは自階層の .md から取る。**触れた階層全部に 1 本ずつ書く**。階層は自己完結している。`normal` は `journal/YYYY-MM-DD/session-NN.md`、project は `projects/<P>/journal/YYYY-MM-DD/session-NN.md`、subproject は `projects/<P>/subprojects/<S>/journal/YYYY-MM-DD/session-NN.md` (その下に段が続く時は `…/subprojects/<S2>/journal/…`、何段でも同じ形) に書く。親とサブの両方を触ったら触れた階層ごとに 1 本ずつ。NN は Step 0 出力の採番をそのまま使い、階層ごとに独立している。Step 0 の検証が `machine:` 行を出す派生は、その label を frontmatter の `pc:` に書く。複数の機械が同じ journal の folder に書く時、起動はこの印で自分の機械の物に絞る。規律は `journal/_README.md`、フォーマットは `journal/_template.md` が持つ。**続きのある仕事は journal に書かず、票が持つ** (client のタブ)。持つ票それぞれに今の状態を書き足し (1 行目が次の 1 手)、票の無い続きの仕事は `tabs ticket new` で開く (操作者の言葉から出た物は `--operator-said`)。票にするのは、その発話のターンの中で終わらない仕事とタブを渡る仕事だけで、1 枚 = 目的 1 つ。続けてよいかは票の出どころの欄 (操作者 / 別のタブ / 自分) が決めるので、手に出所の印は付けない。次の 1 手はエージェントが打つ手で書き、確かめていない見立ては「見立て」と書く。journal に票の id は並べない (`tabs ticket mine` が出す)。client の外の session (`PWA_SID` が無い) は票を持てないので、続きを journal の `## 生きている依頼` に書く (操作者の言葉を「」で原文のまま・範囲・次の 1 手。手ごとに `[操作者]`・`[タブ]`・`[案]`・`[見立て]` の印)
  - **移り** (票の形が入って最初の締めで 1 回): タブのメモの「生きている頼み」と、前の journal の `## 生きている依頼`・`## 次回` のうち終わっていない物を票に開き直し、メモから消す。操作者の原文は `--operator-said` では運べない (取れるのは最後の発話だけ) ので、本文に「」で時刻と一緒に写す。出どころは「自分」になり、続ける前に操作者に見せる側に倒れる
- **操作者が答えた物は、真値 (決まりの file・plan・操作者のメモ) へ入れ、journal の「決めた事」には入れた先の 1 行だけを書く**。中身を journal にもう一度書かない。答えは「はい」の形に限らない。方向を言った時も、操作者自身が案を出した時も答えで、例えば「〜の方が絶対良くね」「〜してもいいよ」が当たる。真値の側に決めた日時と操作者の言葉を添える
  - **`操作者の返事待ち` に書くのは、訊いた後の操作者の発話にその問いへの言及が 1 つも無い物だけ**。書く前に、この session の操作者の発話を問いごとに照らす。context に在るうちに行う
  - Why: 答えの出た問いを「返事待ち」と書くと、次の session が同じ問いを訊き直すか、確かめるために会話の記録を全部読み直して context を食う。journal だけで、何が決まって何が残っているかが読める形にする。操作者が 2 度答えた問いを 2 session 続けて「返事待ち」と書いた実例がある
- **`startup-status.sh` 実行 → 全指標走り切り**: docs-check を内包するので 1 回で済む。エージェント判断で commit まで完遂する。報告は Step 3 締めで 1 行のみ

## Step 3 (直列、必須)

**触った repo ごとに commit する**。親の repo から gitignore された階層の folder が自分の repo を持つ時 (folder 直下に `.git` があり、remote なしでこの PC の中だけの履歴を持つ) は、自分の階層の folder に絞って先に閉じる: `git -C <repo> add -A -- <自分の階層の folder> && git -C <repo> commit -m <message> -- <自分の階層の folder>`。下に子の階層を持つ階層のタブは、子の階層の folder を `':(exclude)<子の階層の folder>'` で外して同じ形で打つ。その repo は pull / push しない。remote が無いため。親の repo は、階層の外の file (親の `rules/` / `.claude/skills/` / `.tooling/` / `profile/` 等) を触った時だけ、下の連続実行で締める。

- **add と commit には、どちらの repo でも自分が書いた path を名指す**。1 本の repo を複数の階層のタブが共有し、それぞれが書きかけを持つ。path を付けない `add -A` は repo 全体の未 commit を拾い、`--` の無い commit は別のタブが stage した物も載せる
  - Why: 締めの commit が、同じ repo を使う別の階層のタブが commit せずに置いていた書きかけ 3 本を拾った。1 本は人の顔が写った画像だった (2026-11-15)

`git add -A -- <自分が書いた path>... && git commit -m <message> -- <自分が書いた path>...` → `git fetch && git rebase --autostash @{u}` → `git push` **必ず連続実行**で締める。取り込みを fetch と rebase に分けるのは、rebase が共有の `FETCH_HEAD` を読まないためで、`git pull` は同じ checkout の別のタブの fetch と重なると `Cannot rebase onto multiple branches` で止まることがある。名指すのは、この会話が Write / Edit / 命令で書いた file と folder で、自分の階層の journal を含む。folder で名指してよいのは、自分の階層の folder の中と、どの階層にも入らない共有の file (親の `rules/` / `.claude/skills/` / `.tooling/` 等) だけで、上か下の別の階層の物は file を 1 本ずつ名指す。別の階層の物を folder で名指すと、番人が commit を止める。同じ checkout の別の階層のタブが stage した物 (`git rm` の削除など) を、folder の名指しで持っていかないためだ。push の直前に取り込み直すのは、session 中に他 PC が push して fast-forward できなくなった分を吸収するため。push が失敗したら、fetch → rebase → push のリトライを 1 サイクル、エージェント自前で行う。2 度目も失敗して conflict が残ったら、操作者へ報告して手動解決する。

複数の PC で同じエージェントを clone している場合、**同期点は開始時の pull とこの Step 3 の 2 つ**。同時起動は避ける。共通基盤 (`profile/` / `rules/` / `.claude/skills/` / `CLAUDE.md` / `.tooling/`) を別 PC が同時に編集していると rebase が止まるので、その時は操作者へ報告。新しい PC の立ち上げは `.claude/skills/base-sync/SKILL.md` が持つ。

## 自動の入れ替えで締める時 (引き金が届いた時)

引き金は client の backend が打つ発話で、1 行目が `Automatic session rollover, sent by the client`、中に `<session-rollover phase="close" reason="context|idle" …>` が在る。context が 60% に届いた作業中のタブか、40% を超えて 50 分静かなタブに届く。締め方は上の Step 0〜3 のまま。違うのは次の 6 つ。

- **引き金だけで締めへ入る**。発動に操作者の了承は要らない
- **作業中なら、区切りまで進めてから締める**。区切りは、次の session が途中から拾える所を指す。書きかけの file を閉じた時、走っている検査の結果を読んだ時、開いた PR や branch の状態を書ける時が当たる。操作者に返していない報告が在れば、締めの前に出す
- **引き金の後に来た仕事は、次の session へ渡す**。まだ答えていない操作者の発話は、引き金と同時に来た物も、締めの途中に届いた物も、`操作者の最後の頼み` に言葉のまま書き、`continue` で起動し直す。新しい session がブリーフィングの後に答える
- **引き金の後の終わり方は、起動し直しの 1 つだけ**。道具が断った・push が通らない・番人が止めた・別のタブの道具が壊れている、のどれでも、このタブで原因を直して打ち直す。自分の道具は自分が直す。操作者や別のタブの返事を待って止まらない。60% を超えたタブが待つと、誰も動かない。直した事は journal に書く
- **journal の `## 入れ替えの時点` と持つ票が引き継ぎの本体**。`## 入れ替えの時点` は毎回書く。続ける物が無い時も書く。新しい session はこの節をブリーフィングで上から読み上げるので、操作者がそのまま読める文で書く
  - 引き金: 時刻 / context の割合 / 静かだったか作業中か。引き金の `reason` と `context_pct` から取る
  - 操作者の最後の頼み: 言葉のまま
  - 進み: 終わった物と途中の物を分けて
  - 操作者の返事待ち: 訊いたまま答えが来ていない問いと、出したまま反応が無い報告。無い時は「なし」と書く
  - 最後の出力: 写さない。操作者は client の画面の右上の 🔖 で、入れ替えの前の最後の答えを読める。書くのは「最後の出力は 🔖 にある」の 1 行と、その答えが何についての物かの 1 行だけ。エージェントに同じ文を 3 度 (答え・journal・次の挨拶) 書かせないため
  - 続ける物は持つ票が持つ (上の Step 2)。新しい session は `tabs ticket mine` の次の 1 手から続ける。動いている票が無ければ、読み上げた後に待つ
- **Step 4 (最後の 1 手)**: Step 3 の push が通ってから打つ。打つとこのタブは約 1 秒で終了し、同じ階層で起動し直される。道具は、この会話が書いた journal に `## 入れ替えの時点` が無い・commit していない・push していない時と、動いているのにこの会話で書き足していない票が在る時 (Step 0 の検査と同じ) は頼まずに止まり、足りない物を 1 行出す。その Step に戻って済ませてから打ち直す

  ```
  tabs rollover <continue|wait>
  ```

  journal は Write / Edit で書く。道具はこの会話の記録から、Write / Edit で書いた journal を探すので、Bash で書いた journal は見つからず、断られる。push は見ない。同じ clone で起動し直すので、push は次の会話の締めが運ぶ。

  **`continue` か `wait` かは、次の 1 手が操作者の答え無しに打てるかで決める**。打てるなら `continue` を使う。起動の後、出どころが操作者か別のタブの票の次の 1 手へ進む。出どころが自分の票の手は、実行の前に操作者へ 1 行で見せて待つ。`wait` で起動した時も、出どころが操作者か別のタブの票の手のうち、送るだけで何も書き換えない手は進める (見立ては先に実物で確かめてから見せる)。作業の途中で区切った時と、続けろという言いつけが生きている間に区切りで報告を出した時がここに当たる。報告は区切りで、操作者待ちではない。操作者へ問いを出していて、その答えで次の 1 手が決まる時だけ、`reason="context"` でも `wait` を使う。起動の後、操作者の答えから続ける。`reason="idle"` は `wait`。階層は道具が決める (`AGENT_TIER`、無い会話は最初の発話から)。session の途中で階層を切り替えた時だけ `--tier <階層>` を付ける

**同じ session で 2 度目の締めは、1 度目の journal に書き足す**。番号は 1 度目の物を使う。

**引き金の締めでは Step 3 の push が止まっても Step 4 を打つ**。commit まで済んでいれば道具は通す。止まった理由は journal に書き、次の session の締めで push する。Step 3 の「操作者報告 + 手動解決」は、操作者の終了発話で締める時だけの扱い。
