# 実装計画書の作り方

## 表は 2 枚に分ける

- **刻みの表** = 何が何より先か (= 依存だけ)。 Done と「止まる線」 はこの表が持つ
- **持ち場の表** = 誰がどの file を持つか (= 同時に書き換わる file の束)。 **起票の時点で書く**
  - Why: 刻みは 1 つの型か 1 つの決定に対応するので、 体 1 つ分の仕事量に足りない。 それを進行の単位に流用すると段取りだけが増えて中身が進まない
  - How: 刻みの表を先に書いてから持ち場を切ると、 後から配り方を差し替える二度手間が出る。 同じ起票で 2 枚出す

## 進行の単位は持ち場だけ

- 進行の見出しは持ち場で書く (= 「刻み N をやる」 は 1 session の単位にならない)
- 持ち場は最終形の像から切る。 **刻みで割ると、 後の刻みで消える物を磨く手間が出る** (= 配り方が transitional shim を作る)
- 1 持ち場 = 1 PR、 差分は大きくてよい (= 戻すのは git)
- **持ち場の数 = 統括の受け取り回数 = 重い検査の回数**。 所要時間を決めるのはここ

## 重い検査は wave ごとに 1 回

- 持ち場ごとに回さず、 同じ wave の成果を積んでから 1 回だけ回す
  - Why: 段階に分けて出すほど、 長い検査がその回数だけ走る
- 赤が出た時に限って持ち場ごとに切り分ける

## 統合する時は中身を運ぶ

- **元の資料を 1 本読んだら、 生きている内容をその場で統合先へ書き写してから次の 1 本へ進む** (= 決定 / 値 / 理由 / file:line / 残件。 読み終えてから索引や数行の要約を作る形は統合にならない)
  - Why: 全部読んでから書くと、 文脈を使い切った所で中身が手元に残っていない。 読んだ量が書いた量を先に越えない順で進める
- **`_archive/` へ移すのは、 中身を統合先へ写し終えた資料だけ**

## 実装に入る前に、 木・名前・値を決め切る

- **実装の回の前に、 どの file をどこに置くか・名前・値を操作者と決め切り、 試作が同じ答えを出す所まで確かめる** (= 頼まれた範囲が、 書く段での決め直し無しに 1 回で閉じる回が理想)
  - Why: 書く段での作り直しは、 決め切っていなかった物の所でだけ出る (= 決まっている物は、 量が多くても書くだけで入る)
  - How: 下の「先に決めておく値」 に、 木と名前も並べる。 決まっていない物が残っている間は、 実装の回を始めずに決める回を置く

## 起票時に並べるもの

- **先に決めておく値** (= 実装で埋めない判断) を推奨つきで全部
- 体へ渡す手順書は **file 1 枚 + 版番号** (= 本文を prompt に写さない、 版を上げたら走っている体へ 1 通)
- 判断が要る刻み (= 読んでから決める / 扇で配る類) は持ち場に混ぜず、 境界を計画書に書く
