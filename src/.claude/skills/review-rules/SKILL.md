# レビューの決まり

**読むのは統括 (= 依頼を受けた本人) で、 網羅は自分が読んだ行で取る**。

- Why: 読む費用は「対象の量 × 読む人数」 で決まる。 書く作業は持ち場が重ならないので体を足しても延べの量は増えないが、 読む作業は足した本数ぶん同じ file を読み直す (= 書く作業の配り方 = `.claude/skills/sub-agent/SKILL.md § 並列で出す時` は、 読む作業には当てはまらない)

## 用途ごとの既定

| 用途 | 統括が読む範囲 | 体 |
|---|---|---|
| 差分 (= PR / commit) | 差分の全行と、 差分が触った file の全体 | 統括だけで読む |
| 1 つの module | その module の src と test を通して | 統括だけで読む |
| 全体 (= 参照実装 / 仕様) | 全行。 束に分けて順に読み、 束ごとに所見を書き出してから次の束へ進む | 操作者が体を選んだ時だけ使う (= § 体を使う時) |
| 設計書と実装の突き合わせ | 設計書から surface の一覧を作り、 1 つずつ実装の file:line に当てる | 統括だけで読む |
| 実データでの確かめ | 自分の手で 1 回通し、 出力の実物を見る | 統括だけで通す |
| 自分が書いた設計書 | 体の所見を 1 件ずつ原本の文に当てる | 書いた本人ではない体に読ませる (= § 自分が書いた設計書) |
| 直しの後の確かめ (= 所見が閉じたか) | 所見を出した時の再現を回し直し、 赤だった物が緑になったのを見る (= 直した側が書いた test だけでは閉じない) | 統括だけで回す |

- 体が出した PR を受け取る時の見方 = `.claude/skills/sub-agent/SKILL.md § 中央 merge の責務`

## 体を使う時 (= 全体の見直しで、 操作者が体を選んだ時)

- **立てる前に見積もりを 2 本並べて出し、 操作者の返事を待つ**
  - 自分で読む場合 = 対象の行数 (= `wc -l` の実測)
  - 体を使う場合 = 本数と、 各体が読む行数の合計 (= 全員に読ませる file は本数ぶん数える)
  - 直近に同じ種類の体を回した実績が journal に在れば、 1 本あたりの token を添える
  - Why: 体の起動の許可 (= `rules/always.md § forbidden`) は量を知って出すもの。 本数の無い許可は量を決めていない
- **許可は出した本数ぶん**。 足す時は、 足す本数と理由を出して訊き直す (= 途中で見つけた穴を埋める体も、 確かめ用の体も同じ)
- **file の束で割り、 各体は自分の束を全部の観点で見る** (= 1 つの file を読む体は 1 本。 観点は割る線にしない)
  - Why: 観点で割ると全員が全部の file を最初から読み、 同じ欠陥を複数の体が別々に報告する
- **全員に要る前提 (= 台帳 / 設計書 / 用語) は統括が 1 回読み、 要点を brief に書いて渡す**
- **束をまたぐ所 (= 入口 / 共通の型 / 束どうしの境目) は統括が自分で読む**
  - Why: 束で割った体は自分の束の中だけを見る。 境目の欠陥は誰の持ち場にも入らない
- 起動の作法 (= prompt / 待ち方 / 受け取り) = `.claude/skills/sub-agent/SKILL.md`

## 自分が書いた設計書

- **書いた本人ではない体に読ませ、 「壊れる」 が 0 件になるまで往復してから次へ進む**。 往復ごとの体は 1 本で、 この用途の起動は許可済みとして扱う (= 見積もりの打診は要らない)。 体の model は `sonnet` (= skill `sub-agent` の頭)
  - Why: 書いた本人は、 書いたつもりの事を補って読む。 自分の見直しで出なかった欠陥が、 体 1 本で 51 件出て、 うち 33 件が原本の文から言えた
- **所見は 4 つの種類に分けて数える**。 往復の引き金になるのは 「壊れる」 だけで、 閉じた後に見つかった細部は、 見つけた時に決めて書く (= 2026-10-22、 操作者「閉じる条件は壊れる 0 件で別にいい」)
  - 壊れる: 使う人の普通のコードが黙って違う結果になる / 文どうしが矛盾する / どれかの言語でその形が書けない
  - 細部: 矛盾は無いが、 その場合の文が無い
  - 意見: 書いてある決めを、 別の形にした方がよいという案
  - 言葉: 書き方の決まり・例・注
  - Why: 書いていない場合の数には終わりが無い。 体は回ごとに深く読んだ所から 30 件前後を拾い、 1 つ決めると隣の場合が見える。 7〜9 往復目で全件は 47 → 43 → 39 とほぼ横ばいで、 壊れるは 13 → 8 → 4 と減った。 人のレビューの前例も同じ形 (= Fagan の inspection は所見を major と minor に分け、 major が直ったのを確かめて終える)
- **体には所見ごとに種類を付けさせ、 「壊れる」 には使う人のどのコードがどう壊れるかを 1 行で書かせる**。 種類は統括が原本に当てて付け直す (= 9 往復目は、 体の壊れる 7 件のうち当たりは 4 件)
- 状態を持つ型は、 「状態 × 出来事」 の地図を道具で数えると、 細部が残りのマスの有限の一覧になる
- 所見は 1 件ずつ原本の文に当てて等級を付け、 直してから次の往復へ渡す (= 同じ所見が戻らない形で)
- **判定の前に、 前の往復の所見と決めを、 触る名前と話題で引く**。 2 回以上触った話題は、 その話題の口と場面を全部並べた表に書き直し、 書き換えた文と同じ名前が出るほかの行を全部読んで揃える
  - Why: 5 往復目の 42 件のうち 40 件が前の往復で触った所、 6 往復目の 66 件のうち 44 件がその日書き換えた行から出た (= 所見が名指した 1 文だけの継ぎ足しが、 次の往復の所見になっていた)

## 確かめの等級 (= 所見 1 件ごとに付ける)

| 等級 | 何をしたか |
|---|---|
| 統括が再現 | 統括が自分で実行し、 出力の実物を見た |
| 体が再現 | 体が実行したと報告した (= 統括は実行していない) |
| 読み | コードを読んで判断した (= 誰も実行していない) |

- **報告は等級ごとの件数で出す** (= 「全 N 件」 の 1 つの数に丸めない)
- **等級を上げるのは、 その等級の確かめを実際にやった時** (= 「統括が再現する」 と言った範囲を体へ回すなら、 回す前に言う)
  - Why: 体の報告は一次ソースで確かめるまで未観測。 統括の再現として数えると、 その上に書いた修正が外れる
