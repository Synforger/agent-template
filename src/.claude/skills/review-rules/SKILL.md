# レビューの決まり

**読むのは統括 (依頼を受けた本人) で、網羅は自分が読んだ行で取る**。

- Why: 読む費用は「対象の量 × 読む人数」で決まる。書く作業は持ち場が重ならないので体を足しても延べの量は増えないが、読む作業は足した本数ぶん同じ file を読み直す。書く作業の配り方は `.claude/skills/sub-agent/SKILL.md § 並列で出す時` にあり、読む作業には当てはまらない

## 用途ごとの既定

| 用途 | 統括が読む範囲 | 体 |
|---|---|---|
| 差分 (PR / commit) | 差分の全行と、差分が触った file の全体 | 統括だけで読む |
| 1 つの module | その module の src と test を通して | 統括だけで読む |
| 全体 (参照実装 / 仕様) | 全行。束に分けて順に読み、束ごとに所見を書き出してから次の束へ進む | 操作者が体を選んだ時だけ使う (§ 体を使う時) |
| 設計書と実装の突き合わせ | 設計書から surface の一覧を作り、1 つずつ実装の file:line に当てる | 統括だけで読む |
| 実データでの確かめ | 自分の手で 1 回通し、出力の実物を見る | 統括だけで通す |
| 設計書・手引き・仕様の文書 (自分が書いた物も) | 全体を読ませて直す往復はしない。写しを消して真値の行を指し、機械の検査で閉じる | 往復には使わない (§ 設計書と手引き) |
| 直しの後の確かめ (所見が閉じたか) | 所見を出した時の再現を回し直し、赤だった物が緑になったのを見る。直した側が書いた test だけでは閉じない | 統括だけで回す |

- 体が出した PR を受け取る時の見方 = `.claude/skills/sub-agent/SKILL.md § 中央 merge の責務`

## 体を使う時 (全体の見直しで、操作者が体を選んだ時)

- **立てる前に見積もりを 2 本並べて出し、操作者の返事を待つ**
  - 自分で読む場合 = 対象の行数 (`wc -l` の実測)
  - 体を使う場合 = 本数と、各体が読む行数の合計。全員に読ませる file は本数ぶん数える
  - 直近に同じ種類の体を回した実績が journal に在れば、1 本あたりの token を添える
  - Why: 体の起動の許可 (`rules/always.md § forbidden`) は量を知って出すもの。本数の無い許可は量を決めていない
- **許可は出した本数ぶん**。足す時は、足す本数と理由を出して訊き直す。途中で見つけた穴を埋める体も、確かめ用の体も同じ
- **file の束で割り、各体は自分の束を全部の観点で見る**。1 つの file を読む体は 1 本で、観点は割る線にしない
  - Why: 観点で割ると全員が全部の file を最初から読み、同じ欠陥を複数の体が別々に報告する
- **全員に要る前提 (台帳 / 設計書 / 用語) は統括が 1 回読み、要点を brief に書いて渡す**
- **束をまたぐ所 (入口 / 共通の型 / 束どうしの境目) は統括が自分で読む**
  - Why: 束で割った体は自分の束の中だけを見る。境目の欠陥は誰の持ち場にも入らない
- 起動の作法 (prompt / 待ち方 / 受け取り) = `.claude/skills/sub-agent/SKILL.md`

## 設計書と手引き (自分が書いた物も、仕様・決まりの文書は全部)

**全体を AI に読ませて、所見を直して、また読ませる往復はしない。** 読み手の「壊れる 0 件」を閉じる条件にしない。

- Why: 2026-10-21〜23 に設計書で 21 回往復し、壊れる 67 件のうち 60 件が、所見を直す時に書き足した文から出た。件数は 0 に近づかなかった。分析の真値は、その設計書を持つ階層の `research/` にある 2026-10-23 のレビューの分析だ。2026-10-26 に同じ階層の手引きで同じ往復を 3 回回し (81 → 59 → 36 件)、2 回目の壊れる 18 件のほとんどは手引きが設計書の決まりを言い直した写しのずれだった。操作者はこれを破壊的行為と見なしている (2026-10-26 [操作者]「また繰り返すの？？もうしんどいよ」「お前がまた繰り返そうとしたことは破壊的行為と俺は見做してる」)
- **読み直しや直しを始める前に、その階層の `research/` の分析を読む**。§ 8 の方針が真値

**所見を受けた時の直し方**

- **文を足さずに消す**: 一番多い原因は同じ事を 2 か所に書いた写し。手引き・下位の文書は、上位の文書 (設計書) の決まりや表を言い直さず、決まりの番号・表の行を指すだけにする。所見が名指した 1 文を書き換えるのではなく、写しの文ごと消す
- **振る舞いの細部 (境目・誤りの種類・場面ごとの答え) は、実装の docstring と試験に 1 か所で置く**。文書に足すと 2 か所目になる
- **言語・ライブラリの動きは、実物で動かすか公式の文書の行を指して書く**

**閉じる条件**

- **機械で言える物だけにする**。台帳で全 file を数える・設計書に無い名前・日付と経緯の語・写しの検査が当たる。検査は、わざと赤になる見本で効くと確かめてから使う
- 読み手の件数は閉じる条件に使わない。全部を読む回の件数は、その回に目に入った数で、残りの数ではないからだ

**AI の読み手を使ってよい所**

- **実装の module ごとの差分**。差分の全行と触った file で、§ 用途ごとの既定の「差分」の行に当たる
- 読み手が同じ物を 2 回壊れると付けたら、直す側は判定せずに持ち主 (操作者) に上げる

## 確かめの等級 (所見 1 件ごとに付ける)

| 等級 | 何をしたか |
|---|---|
| 統括が再現 | 統括が自分で実行し、出力の実物を見た |
| 体が再現 | 体が実行したと報告した。統括は実行していない |
| 読み | コードを読んで判断した。誰も実行していない |

- **報告は等級ごとの件数で出す**。「全 N 件」の 1 つの数には丸めない
- **等級を上げるのは、その等級の確かめを実際にやった時**。「統括が再現する」と言った範囲を体へ回すなら、回す前に言う
  - Why: 体の報告は一次ソースで確かめるまで未観測。統括の再現として数えると、その上に書いた修正が外れる
