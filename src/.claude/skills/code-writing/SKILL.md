# コードの書き方

> **版 1**。 子のタブや体に仕事を渡す時は、 本文に写さず、 この file の path と版を渡す (= 版を上げたら走っている体へ「版 N を読め」 を送る)。
> folder の木 (= どの folder に何を置くか) はこの file の外で、 別に決める。 ここで「共有の置き場」 と書く所の場所はそちらが決める。

## 背景

規則が無いまま体ごとに書くと、 役割の混ざった大きい file が育つ。 2026-10-22 の実測で、 道具の repo 4 本の 1000 行を超える file 4 本 (= 2067 / 1512 / 1132 / 1113 行) は、 どれも役割が 3〜6 種類混ざっていた。 判定と読み書きが混ざると、 試験は file や状態を作ってから全体を通すしかなくなる。 部品が import できない名前の file の中にあると、 使う側は file の path から丸ごと読み込むことになる。

各項の末尾の **[機械]** は、 repo の型の検査で赤にする物 (= 検査が入るまでは書く人が守る)。 印の無い項は、 書く人と、 受け取って読む統括が守る。

## 1. file 1 本に入れる物

- **file 1 本には役割を 1 つだけ入れる**。 役割は次の 4 つのどれか
  - 入口: 命令や hook の main。 引数を読み、 下の物を呼ぶだけ
  - 判定: file・状態・外の命令に触らない計算。 試験から直接呼べる
  - 読み書き: 設定・状態・file・外の命令・網に触る所
  - 部品: 2 か所以上から使われる物 (= § 2)
  - Why: 判定が読み書きと同じ file に在ると、 判定だけを試験できない。 役割が file の名前から読めると、 開かずに場所が決まる
- **メソッドを持つクラスは 1 つ 1 file にし、 file 名はクラス名を snake_case にした物にする**。 そのクラスの中だけで使う手伝いは、 同じ file の主のクラスの下に、 名前の頭に `_` を付けて置く (= 継ぐ元になる手伝いだけは上)
- **メソッドを持たない型 (= 値だけの入れ物・設定・選択肢) は、 それを持つ型の file に書く**。 持ち主が無い型と、 2 つ以上の型が持つ型だけ、 自分の file にする
- **メソッドはクラスの file に全部書く** (= メソッドごとに file を分けると、 クラスの全体が 1 か所で読めなくなる)
- **`__init__.py` は import して並べ直すだけにする** (= 中身はそれぞれの file に置く)
- **クラスの中は 作る口 → 公開の口 → 継ぐ人が書く口 → 中だけの物 の順に並べる**
- **file は 1000 行に収める** (= 試験の file も同じ)。 超えたら行を削るのでなく、 上の 4 つの役割の線で割る **[機械]**
- **file の先頭に、 何をする file か・誰が呼ぶかを書く** (= Python は module の docstring、 shell は 2 行目からの `#`)。 1 行で言えない時は、 役割が混ざっている合図 **[機械]**

## 2. 部品の分け方

- **同じ処理は持ち主の file に 1 つだけ置き、 2 か所目はそこから import する** (= 写すと片方だけ直って食い違う)
- **3 か所目で使う時に、 共有の置き場へ移す**。 入れるのは、 名前が付く仕組みで、 何か所からも使われ、 量がある物。 小さい道具は、 その仕事を本来やっている側に置いたままにし、 他は import する
- **部品は import できる file に置く** (= file の path から丸ごと読み込む形 `importlib.util.spec_from_file_location` で部品を取り込むのは、 名前か置き場が import できない合図。 file の名前と置き場を直す) **[機械]**
- **公開の型が使う型 (= 継ぐ元・変数・引数・返る型) は全部公開する**。 中の作りの型を公開の型の継ぐ元にするのは、 公開の型の中身が外から読めなくなるので避け、 公開の側へ出す

## 3. 名前

- **Python の file 名は全部 snake_case にする** (= import できる名前)。 人が打つ命令の名前は入口の側 (= Taskfile・pyproject の scripts・shim) で付ける **[機械]**
- **何かを変える口は動詞にし、 同じ動作は全体で同じ動詞を使う**
  - 足す・外す = `add` / `remove`、 動かす・止める = `start` / `stop`、 開く・閉じる = `open` / `close`、 文や file との出し入れ = `load` / `save`、 一覧 = `list`
  - 値を返すだけの口は返す物の名詞、 変えた写しを返す口は `with_<何を>`、 出来合いを作る口はできる物の名前
- **変数は名詞にし、 略さずに書く**。 並びは複数形、 真偽は肯定の言い方 (= `is_open`)、 単位は名前の後ろ (= `_ms`・`_hz`・`_bytes`)、 数は `_count`、 関数を入れる変数も名詞 (= `callback`)
- **クラスは単独で意味を持つ物ならその物の名前にする**。 状態は「表す物 + `State`」、 設定は「持ち主 + `Config`」、 部品は「直近の持ち主 + 中身」、 選択肢の型は「持つ型 + 欄の名前」
- **作る時の引数は、 入る変数と同じ名前にする**。 省ける引数は keyword でだけ渡せる形 (= `*` の後ろ) にする
- **数の値は名前の付いた定数にする** (= file の先頭に置く。 閾値は実測と倍率で書く)

## 4. 説明

- **docstring は使う人に向けて、 何のための物かの 1 文から始める**
- **`#` のコメントには、 コードから読めない理由だけを書く**。 経緯・日付・版・Issue の番号・PR の番号は commit と決めの記録に置き、 コードの中には置かない **[機械]**
- **使わなくなったコードは消す** (= 戻したい時は git の履歴から取る。 コメントにして残した行は検査で赤) **[機械]**
- **やり残しは `TODO: <やる事>` の 1 つの形で書く** (= 形を揃えると検査で一覧にできる) **[機械]**
- **1 つの関数の中の説明は 1 か所にまとめる**
- **コメントと docstring の言語は読者で決める**。 公開の repo は英語、 それ以外 (= エージェントの体・会社の repo) は日本語 **[機械: 公開の repo]**

## 5. コードの形

- **型の注釈を全部の関数の引数と返り値に付ける** **[機械]**
- **値の確かめは公開の口の入口でだけ行う** (= 中では確かめ済みの値として扱う)
- **関数にするのは、 名前で言える塊だけにする** (= 1 回しか使わない数行は、 名前が付く時だけ切り出す)
- **開く物は `close` を持たせ、 `with` で使える形にする**
- **一覧を返す口は、 無い時に空の並びを返す**。 1 つを返す口は、 無い時に `None` を返す
- **import は絶対 import で書く**
- **shell は命令をつなぐだけにする**。 分岐や文字列の加工が入ったら Python の file に出し、 shell からはその file を呼ぶ (= shell の中に Python を書くと lint も試験も届かず、 引用符の中で壊れても気づけない) **[機械]**

## 6. 外れる時

- **規則から外れる所は、 外れる理由をその file の先頭の説明に書く** (= 理由の無い外れは直す。 理由が他の file にも効くなら、 この skill の版を上げて規則の側を直す)
- **既存の file は、 新しく書く部分から規則に従う**。 割る・名前を変えるのは、 その file だけを扱う PR で行う (= 置き場の変更と中身の変更を同じ commit に混ぜると、 差分が読めなくなる)
