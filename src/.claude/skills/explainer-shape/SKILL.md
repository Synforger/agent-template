# 説明のページの見せ方

置き場・横の目次・タブのトップページ・確かめの script は skill `explainer-pages` の § 説明のページ。

## ページに求める事

- **ページにするのは、図・表・数字・実物で見せる物が在り、後で開き直す規模の説明**。文章で足りる答えとその場の理解の図はチャットに出し、人に共有する物はスライドにする (2026-11-27 [操作者]「文章だけならチャットでよい」)
- **見せ方は中身で選ぶ**。流れ・親子・位置は図、同じ軸の比べと状態は表、量と推移はグラフ、画面・データ・出力は実物
- **開いた所でページの問いと答えが読め、結論を決める数に出所が付き、全量は下か奥に在る**

## 1 本の中の並べ方

- 長い説明は 1 本の HTML の中をタブで章に分け、全部のタブの目次を付ける
- **1 つの頼み (例えば会議の宿題) の結果は、会議の枝の「会議のページ」に頼まれた事の表を置いて返す**。1 件 1 行で、列は「頼まれた事」「やった事」「分かった事」「残り」。「頼まれた事」には言った人の言葉と記録のその時刻へのリンクを、「分かった事」には答えを持つ検証か部品のページへのリンクと出所を入れる。答えの中身はそれぞれの枝のページに書く
  - Why: 中身が揃っていても、頼まれた事との対応が無いと操作者が自分で突き合わせる (2026-10-26 [操作者]「会議で何を求められて、何をやったのかが全然見えない。結局自分で見ないと分からない」)
- **段ごとに全部測った値 (例えば処理時間や量の内訳) を見せるページは、上から結論・流れの図・悪い所・全量の順に並べる**
  - 結論: その値で何が決まるか (例えば処理時間から、答えを出せる間隔) を、今と直した時で並べる
  - 流れの図: 大きな単位の箱を入力から出力の順に並べ、色の濃さを全体の中の割合にし、直しや指摘のある箱に印を付ける。箱を押すと全量の表の行へ飛ぶ
  - 悪い所: 重い順の上位を、なぜか・直しと効きの確かさ・受けた指摘と実物・コードの位置を付けて並べる
  - 全量: 表は入力から出力の順で、各行にコードの位置と図へ戻るリンクを付ける。並びの真値は data の file に置き、並べ替えたら数が変わらないことを元の表と突き合わせる
  - Why: 全部の値を並べただけではどこを見るかが分からず、名前の順の表は処理の順に読めない (2026-10-27 [操作者]「入力から出口にかけてやって欲しい」)

## 中身の木

- **ページの置き場は中身で決める**。1 つの物の説明は、調べた日や会議の回によらず、その物の枝の 1 ページに集めて書き足す。新しいページは、まだページの無い部品や検証の時だけ作る。日付の順は検証と会議の一覧だけ
  - 枝の例は、前提・元の資料・実装・部品ごとの仕組み (1 部品 1 ページ)・結果・検証 (1 本 1 ページ)・会議。仕事で変えてよい
  - Why: 回ごとに段を足すと 1 つの話が散り、入口が消える (2026-11-05 [操作者]「定例で分けるんじゃなくて、全体像として調べたところ全部正しい場所に置いて欲しい」「モデルの説明ならモデルの説明の場所に置くべき。いつやったとか関係なく」「必要な時に必要なページを見に行くことが全然できない」)
- **階層は枝 (h3) とページの 2 段にし、枝が多い時だけ h2 の段で束ねる**。左の一覧は枝を畳んで出し、今のページの枝を開く。枝の中の 1 つの folder に 2 本以上あれば、その folder でも畳む
- **新しく足したページのリンクには `data-added="YYYY-MM-DD"` を付ける**。部品が新しい順の 3 件を左の一覧の上と、トップの `data-toc-new` の要素に出す。全部のページは枝の下に置いたままにする
  - Why: 全部を 1 列に並べると探せない (2026-11-27 [操作者]「今サイドバーにずらっと並んでいてやりにくい」「新しく足したページは 3 件までにし、その下へまとめる所を作って入れてほしい」)
- **トップページは、いつも今の全体像だけを書き、上書きで直す**。何を確かめる仕事か・今の答え (分かった事・分かっていない事・次にやる事)・数の要約・全部の枝を並べる。枝の見出しの下にその枝の全部のページへの直のリンクを置き、`data-toc-pages` を付けた要素 (`<section data-toc-pages>` など) で囲む。左の一覧はそこだけを読み、リンクの名前でページを並べる
  - Why: 操作者は開いた時に今を知りたい (2026-11-05 [操作者]「常に全体がどうなってるのかをちゃんと書くべき」)
- **ページの中の節の順は、種類ごとに決まった順にする**
  - 部品のページ: 何をするか・入口と出口の形・重みか計算か・元の資料での作り・今回の作り・実物・この部品の検証へのリンク・コードの在処
  - 検証のページ: 問い (誰がいつ訊いたか)・答え・やった事・結果・まだ言えない事・関わる部品へのリンク・出所
- **専門の語を使うページには「言葉」の表を置き、列は「通り名 (英語の原語)」「このページでの意味」にする**。本文は分野の通り名で書く。英語の原語を書けない語は自作の言い換えなので通り名に戻す
  - Why: 起動で読む「通り名を使う」の 1 行は書く瞬間に照らせず、peak learning rate を「山」、heatmap を「熱の地図」、gradient clipping を「切り詰め」と書いた (2026-11-12 [操作者]「山ってなんなん、、、またやったお前」)
- **ページどうしを全部リンクでつなぐ** (検証と部品は両向き、会議から答えの検証へ)。検証のページを足したら、部品のページの「この部品の検証」にも 1 行足す

## 見本

操作者が作った物について言った言葉は、エージェントごとの file `samples.md` (skill `explainer-pages` と同じ folder。型は配らない) に積む。**`samples.md` が在れば、ページを作る・直す前に、作る物の種類の行を読んで従う**。この skill と食い違ったら `samples.md` の操作者の言葉が勝つ
