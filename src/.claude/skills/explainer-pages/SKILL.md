# 伝え方

相手が誰かで 3 つに分かれる。 常時効く分は `profile/profile.md` と `rules/always.md` が持ち、 ここは場面でだけ効く作法を持つ。

| 相手 | 渡す物 | 節 |
|---|---|---|
| 他チーム・他エージェント・別のタブ | 依頼文 | § 依頼文 |
| 操作者 (= レビューや判断のために読む) | md | § 操作者に見せる文書 |
| 操作者 (= 自分で理解したい) | HTML のページ | § 説明のページ |

## 依頼文

別のタブへの送り方 (= 宛先・道具・届かなかった時) は、 client の skill が持つ。 ここは**相手に頼む文**の作法だけ。

操作者が中継する相手でも、 タブどうしで直に送る相手でも、 往復が増えると誰かの手間がその回数分増える。

- **1 通で完結させる**: 用件・困っている事実・判断に必要な材料を全部入れる (= 聞き返しが要る書き方が往復を生む)
- **こちらの用件だけを書く**: 実装の形・工数・順序は相手の判断に残す (= 「〜すれば即対応できます」 は相手の作業を決めつける形)
- **形式を安定させる**: 用件 → なぜ必要か (= こちら側の事実) → 判断を委ねる範囲。 毎回同じ並びで書く
  - Why: 前提を docstring だけで立てて往復が出た件と、 実装案を断定しすぎて相手の確認を生んだ件、 どちらも中継の手間になった

## 操作者に見せる文書

操作者が見る・レビューする md (= レビュー用の計画書・下書き・まとめ) の並べ方。

- **操作者に見てほしい物 (= 案・決めてほしい事・答え) を、 file の一番上に置く**
  - Why: 書いた順に下へ足すと、 見てほしい物が経緯の間に埋もれる。 評価の目標の下書きで、 書き直しの案が中ほどに埋もれ、 並べ替えを求められた
- **経緯 (= 会議の解析・前の版・調べた事) は、 その下に順序を付けて置く** (= 時系列か新しい順かを決め、 見出しで分ける)
- **後から案を足した時も、 並べ直してから渡す**
- **推奨 (= 変更の案) は太字にし、 1 件ずつ空行か箇条の印で区切る**
  - Why: 行頭が太字の行を空行なしで並べると、 Markdown が全部を 1 つの段落につなぐ。 レビューの所見 63 件の推奨が 1 つの塊になり、 読めなかった
- 構造の決まりが既にある文書 (= 設計書・実装計画書・journal・テンプレートを持つ文書) は、 その決まりに従う。 この並べ方は、 決まりが無い時の既定

## 説明のページ

### 背景 / 動機

計画書のような決めの文書とは別に、 操作者が自分で理解するための「説明の文書」がある。 操作者は図・表・数字で見える形の資料を随時ほしがり、 その形は HTML のウェブページが一番見やすい。 ページの置き場と辿り方を毎回同じにすると、 エージェントは説明が要る時に何を作ればよいかが決まり、 操作者は「どこに何があるか」 をタブのメモから辿れる。

### 置き場

```
<階層>/pages/
├── index.html        階層のトップ (= タブの一覧。 読める名前はここに出す)
├── _template-tab/    タブの folder の雛形 (= index.html と memo.md)
└── <タブの id>/      タブごと (= id は入れ替えでも変わらない)
    ├── index.html    そのタブのトップページ (= 説明へのリンク)
    ├── memo.md       タブのメモ (= client の 📋 が開く。 git から外す)
    └── <説明>.html   説明のページ (+ data/ と src/ で組み直せる形)
```

- **階層はタブを起動した階層** (= 親の階層で起動したタブは親の階層の `pages/`)。 folder の運用の真値は `pages/_README.md`
- **説明は HTML のページにする** (= 図・表・数字で見せる。 会話の外の公開の場には置かず、 手元の file にしてエージェントの repo に commit して残す)
- **タブの folder は雛形 `pages/_template-tab/` を写して作る**。 階層のトップ `pages/index.html` には、 新しいタブを 1 行足す
- 1 つの説明が長い時は、 1 本の HTML の中をタブで章に分け、 全部のタブの目次を付ける
- **図のデータは、 作るための小さな script でページに埋め込み、 元のデータはタブの folder の `data/` と `src/` に置く** (= ページだけ開いても見え、 作り直しは script を回すだけで済む)

### 運用

- **メモの先頭に、 「このタブは何か」・起動した階層・そのタブのトップページの path を置く** (= 雛形 = `pages/_template-tab/memo.md`。 path は、 そのエージェントの path の書き方の決まりに従う)
  - Why: 操作者はメモから辿って全部の説明に届き、 理解の往復が絵で早く進んだ
  - メモの本文は、 この頭書きの下に書く
- **資料 (= スライド・文書) を作る時は、 ページを元にする** (= 説明の真値はページで、 資料はそこから組み直す出力。 社内・社外へ出す時は、 ページを元に pptx などへ書き換える。 資料の作法の skill を持つエージェントは、 それに従う)
- **渡す前に、 画面なしのブラウザで、 幅 390 px と 1280 px の 2 つで、 はみ出しと JS の error を見る** (= 手順の skill `browser-use` を持つエージェントは、 それに従う)
- **ページは全部残す** (= 社内・社外へ出す資料の元になる。 古くなったページも、 階層のトップからの辿り方で今の物と分けて置いておく)

### 例外 / 適用範囲

- 計画書・設計書のような決めの文書は対象外 (= それぞれの決まりに従う)
