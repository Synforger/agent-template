# 説明のページ

## 背景 / 動機

計画書のような決めの文書とは別に、操作者が自分で理解するための「説明の文書」がある。操作者は図・表・数字で見える形の資料を随時ほしがり、その形は HTML のウェブページが一番見やすい。ページの置き場と辿り方を毎回同じにすると、エージェントは説明が要る時に何を作ればよいかが決まり、操作者は「どこに何があるか」をタブのメモから辿れる。

## 運用

- **説明は HTML のページにする** (= 図・表・数字で見せる。会話の外の公開の場には置かず、手元の file にする)
- **置き場は `explainer/` で、トップページ `index.html` から全部のページへ、階層の構造のリンクで辿れるようにする**
  - 作業 folder がある階層: `<作業 folder>/explainer/`。作業 folder が人と共有する git の repo なら、その repo の決まりに従って置けるかを先に確かめ、置けない時は次の置き場にする
  - 作業 folder が無い階層 (= 親の階層など): エージェントのその階層の `<階層>/research/explainer/`
  - 1 つの説明が長い時は、1 本の HTML の中をタブで章に分け、全部のタブの目次を付ける
- **図のデータは、作るための小さな script でページに埋め込み、元のデータは隣の folder に置く** (= ページだけ開いても見え、作り直しは script を回すだけで済む)
- **全部のタブのメモの先頭に、「このタブは何か」・起動した階層・トップページの path を置く** (= メモ = `<階層>/notes/<タブの id>.md`。雛形 = この skill の `tab-note.md`。path は、そのエージェントの path の書き方の決まりに従う)
  - Why: 操作者はメモから辿って全部の説明に届き、理解の往復が絵で早く進んだ
- **資料 (= スライド・文書) を作る時は、このページを元にする** (= 説明の真値はページで、資料はそこから組み直す出力。社内・社外へ出す時は、ページを元に pptx などへ書き換える。資料の作法の skill を持つエージェントは、それに従う)
- **渡す前に、画面なしのブラウザで、幅 390 px と 1280 px の 2 つで、はみ出しと JS の error を見る** (= 手順の skill `browser-use` を持つエージェントは、それに従う)
- **ページは全部残す** (= 社内・社外へ出す資料の元になる。古くなったページも、トップページからの辿り方で今の物と分けて置いておく)

## 例外 / 適用範囲

- 計画書・設計書のような決めの文書は対象外 (= それぞれの決まりに従う)
- 操作者に見せる md の並べ方は、文書の書き方の skill (= `request-writing`) を持つエージェントは、それに従う
