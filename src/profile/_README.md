# profile/ の運用

エージェントがユーザとの協働に使うプロファイル置き場。 **`profile.md` 1 file** (= 常時 load、 上限は frontmatter `capacity:` 宣言が真値)。

**分けるのは意味の切れ目がある時だけ**。 容量だけを理由に分けると、 同じ内容が複数 file に散って真値が割れる (= シチュエーション別 5 file に分けた構成を 1 本へ戻した実測がこれ)。

## 書き方

1. **個別事例を書かない**: 日付 / セッション番号 / commit hash / 特定リポ名 / 特定機能名は書かない
2. **「行動ルール」 で書く**: 「ユーザは X を嫌う」 でなく「X はしない」 (= エージェントへの挙動指示として読める形)
3. **1 項目 1-2 行**: 補足 / 経緯 / 例示は置かず、 理由 1 行だけ添える
4. **同種は統合**: 似た指摘は 1 項目に圧縮する

## 何を残すか

残す = **反復して効くもの** (= 2 回以上の指摘) / ユーザの核・思考様式・価値観 / エージェントの判断軸として常時参照するもの。

書かない:

- **1 度だけの事例から作る保険** (= 再発したら狭く書き戻す)
- 特定プロジェクト / 特定機能に固有の判断 (= `projects/<P>/` 側が持つ)
- 特定の作業中にしか効かないもの (= `rules/lazy/` 側が持つ)
- 機構が既に守っているもの (= script が止めるものを文章で二重に書かない)
- セッション固有の経緯描写 (= journal が持つ)

## ライフサイクル

- **読む**: session 開始時に全文 Read
- **追記**: 新しい一面 / 好み / 癖が見えたら終了時 Step 1 でエージェント判断で追記する (= 事前確認は要らない)。 上の「何を残すか」 に照らして該当しなければ、 journal に事実として残すだけにする
- **容量超過**: 同 session 内に発火実績の下位から削る (= 判定はルール台帳の lazy が持つ)。 文字数が稼げるものから削る形は採らない
