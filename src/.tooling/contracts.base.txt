# 型が配る約束の表 (= 型が配る道具が外に対して守る事 1 行 ↔ それを試すテスト 1 本、 の真値)
#
# 型が配り、 派生は書かない (= `.synced-paths.txt` に載っていて、 取り込みのたびに上書きされる)。
# 派生だけの道具の約束は、 派生の `.tooling/contracts.txt` に書く。 検査は 2 枚を足して読み、 同じ行が両方に在れば赤にする。
# 型の行を派生で持たない時は、 派生の file に `!<対象>  # <理由>` と書く。
#
# 検査 = .tooling/docs-check/check-declarations.py
#   - `.tooling/` の道具は、 どれも 2 枚のどちらかの表に 1 行以上載っている (= 何を守る物か言えない道具を置かない)
#   - `tests/` のテストは、 どれも表の行に載っている (= 約束に紐付かないテストを置かない)
#   - 行が指す道具とテストは実在する
# 書式 = <対象の道具> | <守るテスト。 無ければ -> | <約束 1 文>   (= path は .tooling/ から)
#   対象の頭の `?` = 機械全体の hook (= 型の `.synced-paths.txt` の `# @machine-wide` の物)。 対象もテストも無い派生ではその行を見ない
#
# テストを足してよいのは 2 つの時だけ:
#   1. 約束の行を足した時 (= その行のテストとして)
#   2. 実際に踏んだ不具合を再現する 1 件を、 その約束を守っている既存のテストへ足す時
# 約束は外から見える物で書く (= 出力 / 止める・通すの判定 / 書かれる file の形。 中の関数の振る舞いは約束にしない)。
# `-` の行は「守られていない約束」 で、 検査が数で出す。 足す前に、 同じ対象の行が既に何を守っているかをここで読む。
